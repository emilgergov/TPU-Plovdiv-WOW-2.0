# КТ134 — вариант А: автоматично изолирано осигуряване на тестов Cloudflare
Дата: 25.11.2026 г. Работен клон: `kt134-auto-mode-isolated`.

## Реално изработено
- `kt134-auto/kt134-isolated-cloudflare-provision.mjs` е изпълним GitHub Actions Node инструмент с два режима:
  - `plan`: GET-only; сравнява protected KT125 gateway, backend, D1 и имената на отделните staging ресурси; при недоказано R2 право прекратява преди записи.
  - `create`: само при отделно ръчно пуснат workflow с точен маркер `CREATE_KT134_ISOLATED_ONLY`; отказва неизвестни/съществуващи/продукционни ресурси, проверява имената и текущия Cloudflare акаунт, не изтрива и не презаписва. Създаването на нови ресурси може да влияе на Cloudflare таксуването.
- `.github/workflows/kt134-isolated-staging-provision.yml` автоматично изпълнява само `plan` на push в изолирания клон. `create` не може да стартира от обикновен push; изисква `workflow_dispatch` с изрично потвърждение. Ако интерфейсът на GitHub не предлага ръчно изпълнение за branch-only workflow, това трябва да се реши с отделна приета процедура, а не с пробив в защитата.
- Предвидено е **отделно** `kt134-isolated-d1-2026`, `kt134-isolated-r2-2026` и `kt134-isolated-sandbox-2026`. Последният при създаване е неактивен Worker, който връща HTTP 503, без маршрути, без secrets и без service binding към продукционния КТ125. Не представлява втори експертен модул.

## Реално изпълнен тест
Успешен GET-only `plan`: https://github.com/emilgergov/TPU-Plovdiv-WOW-2.0/actions/runs/45517127669

Логът потвърди:
- Действащият защитен gateway/backend може да се чете (без публикуване на кода).
- D1 enumeration може да се чете.
- **R2 bucket enumeration HTTP 403**. Създаването е **BLOCKED**, няма създадени ресурси и няма опит за POST/PUT.
- Действащите КТ133, КТ125, D1 и R2 не са променени от този workflow.

## Единствено необходимо външно действие
От администратор на същия Cloudflare акаунт: осигуряване на подходящ account-scoped token с `Workers R2 Storage: Edit/Write` за списък и създаване на изолирани bucket-и, а за бъдещото осигуряване и `D1: Edit` плюс `Workers Scripts: Edit`. Текущият GitHub secret `CLOUDFLARE_API_TOKEN` трябва да сочи към надлежно разрешен токен, без стойността му да се публикува в чата или в хранилището. Правото за R2 е доказано липсващо/недостъпно при този токен; правата за D1/Workers запис не са доказани.

След корекцията: пуска се read-only `plan` отново, след положителен резултат — само ръчно одобрено `create`. Няма основание да се опитва deploy към KT133 или към живия KT125.
