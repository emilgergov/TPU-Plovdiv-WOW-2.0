# КТ134-Ж.6 — атомарно съвпадение на архивирания Word и експертните права
Дата: 25.11.2026 г.
Клон: `kt134-auto-mode-isolated` (без production deploy)

## Установен и поправен пропуск
В тестовата атомарна SQL операция от КТ134-Ж.4 се сравняваше `binding_sha256`, но липсваше отделно сравнение на `word_sha256`. Това допускаше несъответстващ SHA на архива на нивото на записващата SQL операция, независимо от предварителните проверки.

Промених:
- `kt134-test-atomic-approval.mjs`: изисква `wordSha256` и го предава като отделен параметър в единствения условен D1 UPDATE;
- `KT134_TEST_ATOMIC_APPROVAL.sql`: отделен `word_sha256=?6` и преместен actor ID на `?7`;
- `test_atomic_approval_sqlite.py`: допълнителен тест за подменен SHA на самия DOCX;
- `kt134-test-atomic-approval.test.mjs`: проверка за допълнителния SQL параметър и отказ при липсващ Word SHA.

## Проверка
Изпълних 8 локални SQLite проверки върху еквивалентна самостоятелна тестова схема и същото условие на SQL UPDATE: един успешен запис, повторно одобрение, отнети права, променена ревизия, подменен Word SHA, подменен preview binding SHA, чужд експерт, superseded проект. Всички 8 локални проверки преминаха. Това НЕ заменя потвърден GitHub Actions run за целия проект и НЕ доказва реална Cloudflare/KТ125 интеграция.

## Граница за KT125 реална авторизация
`kt134_test_approval_acl` е само синтетичен тестов модел. Преди включване в реалния Worker условието `EXISTS` трябва да бъде заменено с авторитетната схема за активна локална KT125 сесия, собственик/делегирани права и статус на преписката. Защитата се проверява отново ВЪТРЕ в атомарната транзакция, не само преди AI обработката. Не се копират секрети или частен KT125 код в публичния GitHub.

## Неизпълнени предпоставки
- потвърден GitHub Actions CI run на всички нови тестове;
- проверени реални Cloudflare права и отделна тестова среда;
- транзакционна адаптация към реалната KT125 ACL;
- пълен жив автоматичен маршрут и експертна приемка.

Стабилната публична КТ133 и main не са променяни.
