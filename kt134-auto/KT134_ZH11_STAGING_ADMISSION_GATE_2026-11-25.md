# КТ134-Ж.11 — автоматична защита на тестовата среда

Дата: 25.11.2026 г. Изолираният клон е `kt134-auto-mode-isolated`.

## Реално реализирано
- `kt134-staging-admission.mjs`: защитен отказ при липса на доказано отделни Worker, D1 и R2, потвърдени GET от Cloudflare, и независимо удостоверена изолация на R2. Никога не приема продукционния КТ133/КТ125 Worker или D1 за тестови ресурси; отказва и ако идентичността на продукционния Worker/D1 не е сигурна.
- `kt134-staging-admission.test.mjs`: тестове за всички условия и откази, включително липсваща производствена идентичност.
- `.github/workflows/kt134-cloudflare-github-first-readonly.yml`: нова read-only проверка на ресурсите през GitHub variables, без публикуване на идентификатори/имена на ресурси, без секрети, без PUT/POST/DELETE. Изрично съобщава „BLOCKED“, когато средата не е доказано изолирана. Дори резултат „ELIGIBLE“ НЕ дава разрешение за deploy: изисква се отделна проверка и приемка.

## Реални проверки
- [GitHub Actions — staging admission](https://github.com/emilgergov/TPU-Plovdiv-WOW-2.0/actions/runs/45506364655): успешно изпълнение на безопасния audit workflow; admission **BLOCKED** с отказ по всичките 7 критерия за несъздадена/недоказана staging среда.
- [GitHub Actions — KT134 isolated tests](https://github.com/emilgergov/TPU-Plovdiv-WOW-2.0/actions/runs/45506313698): 202 Node проверки + 16 SQLite проверки, всички успешни към тази версия.
- След тези проверки са добавени още две тестови защити: неизвестна продукционна идентичност и невалиден D1 UUID. За тях се изисква успешно ново CI изпълнение.

## Какво е доказано за Cloudflare
- Реален gateway и backend KT125 четими през GitHub Cloudflare token.
- Налична е само 1 видима D1 и няма открита отделна тестова база; 7 Worker-а, без ясно обозначен тестов KT134 Worker.
- R2 listing: HTTP 403. Това е липса на доказан достъп, не доказателство за липса на R2.
- КТ134 автоматичен маршрут все още липсва от действащия КТ125.
- Публикуваната КТ133 не е изменена.

## Еднократната външна предпоставка
Преди истински KT134 тест трябва да има **отделен** тестов Worker, отделна D1 база и частен тестов R2, с минимални права на GitHub Actions за тях. Изисква се потвърждение, че R2 bucket-ът няма продукционни данни, и защита срещу връзка към действителния KT125. Никакъв опит за създаване на платени ресурси или за разширяване на права не е предприет автоматично.

Практически път: настройката се прави еднократно през Cloudflare или чрез предварително разрешен отделен инфраструктурен workflow. След като ресурсите са налице и имената им са въведени като GitHub repository variables, `kt134-cloudflare-github-first-readonly.yml` ще ги провери без да изнася идентификатори или секрети.

Без осигурена изолирана среда НЕ се допуска D1 миграция, R2 запис, Deploy, живо одобрение на решение или изменение на КТ133.
